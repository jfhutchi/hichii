# Task 3: NaN-defined emission and compatible shader-cache migration

## Scope and provenance

The requested direct-parent integration already includes Lichii PR432 at
`2e69168aae8`, from `d3697a8fbbb37ab5527ed580b0e3eb8db06ce5e2` and
`4437a12176299f71fe957d21d30ded4b5f9b5261`. Its NMin/NMax emitter changes and
cache version 54 are adopted, not duplicated. No version 55 bump is needed:
this task adds regression coverage and fixes migration selection, without new
emitter semantics.

The NVIDIA min/max and saturation behavior underlying the adopted change is
documented behavior. It is not a direct Maxwell/Ampere guest capture. The tests
below check translation and emitted instructions; they do not execute shaders on
a GPU or establish Radeon pixel correctness, NaN payload behavior, frame rates,
or resolution of the reported haze/green water in a running game.

The #295 prerequisite remains in `emit_spirv_memory.cpp`: `VectorViewIsExact`
requires descriptor aliasing plus suitable known immediate or device alignment;
64/128-bit storage loads and stores otherwise use scalar words. The existing
storage-alignment regression suite is included in validation.

## Migration policy

`MigrateVulkanShaderCache` is called by `PipelineCache::LoadDiskResources`.
It selects compatible shader environments in order v53, then v52, and copies
only the selected generation's `vulkan_used` file. Missing usage data is valid
and never causes the other generation's usage list to be imported. Existing
environment destinations leave both destination files alone; existing usage
destinations are preserved. Sources are preserved byte-for-byte. The existing
header-checked temporary-copy/rename implementation retains interrupted-copy
recovery.

The opaque `vulkan_pipelines` driver blob is separate. Its existing explicit v52
migration policy is retained, with the distinct `yuzuvkch` magic and driver-side
validation. Tests verify byte-preserving driver-copy behavior and separation
from shader-environment migration. Rewriting that blob's outer version does not
retranslate shader code. The native integration regression exercises the
`vulkan` environment path independently.

## Regression coverage

- Selection and pairing: both source versions, v52 only, invalid v53 header,
  selected v53 with no usage list, existing environment with and without usage
  data, existing usage destination, no compatible source, interrupted copy.
- Emission matrix: f32/f64 min/max, saturation and clamp; native f16 and the
  real `LowerFp16ToFp32` fallback for saturation/clamp; native f16x2 and packed
  f32x2 CAS min/max helpers; both values of `has_broken_spirv_clamp`.
- Native cache integration: a synthetic Ampere S2R/FMNMX/STS/EXIT compute
  program is lowered using the production frontend and packed with scheduling
  words and its native address map. `SerializePipeline` writes a v53 native
  environment and compute key. Production migration and `LoadPipelines` restore
  it; the test checks the key, native flags/address map, workgroup size and shared
  memory, then runs CFG construction, `TranslateProgram` and `EmitSPIRV`.
  Two dynamic shared stores retain the min/max operations through optimization.
  The module must contain one NMin and one NMax, with no FMin/FMax/FClamp.
  This fixture is deliberately synthetic, not represented as a game capture.

## Red/green evidence

The original hardcoded v52 behavior was first extracted unchanged from
`LoadDiskResources` into the production helper to permit a real filesystem
regression. Before implementing selection, the new tests failed 16 of 94
assertions (one failing case, one passing driver-copy case). Failures included
choosing v52 instead of v53 and importing unrelated v52 usage data when no
environment was migrated or the selected generation had no list.
Log: `.local-tools/task3-migration-red-tests.log`.

After implementing selection, the migration and NaN tests passed 5 cases /
2,424 assertions. A deliberately isolated mutation then changed NMin/NMax to
FMin/FMax in both emitter files, and restored FClamp for the ordinary clamp
profile (FMin/FMax composition for the broken-clamp profile). All 3 selected
cases failed, with 38 failed assertions of 2,306, including the cached-native
retranslation case. This is mutation evidence, not a claim that the merged
parent baseline lacked PR432. Log:
`.local-tools/task3-emitter-mutation-red-tests.log`.

The original production bytes were restored and checked against private
backups. The initial file-copy restoration preserved old timestamps, so Ninja
temporarily reused the mutated objects; that run is not green evidence. Rewriting
the exact original bytes triggered compilation of both emitter units and relinked
the test and CLI executables. Focused tests then passed 17 cases / 201,545
assertions. Log: `.local-tools/task3-focused-restored-green-tests.log`.

Validator checking identified that the adopted test fixture's SPIR-V 1.3 profile
was incompatible with the entry-point interface containing storage/workgroup
variables. The fixtures now request SPIR-V 1.5 and final validation uses Vulkan
1.2. This changes test profiles only. Private header-only diagnostic probes
were not counted as emitted-module validation; final evidence uses regenerated
modules from the rebuilt tests.
