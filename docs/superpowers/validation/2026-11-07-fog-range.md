## Adaptation

Read-only table pointers now reach the continuous mapped range, bounded by the
backend storage range and 1 GiB. The effective range participates in the binding
cache key. Layout lengths saturate in u64 before narrowing to u32. The actual
alignment prefix consumes the range budget; continuity is checked from the
aligned base. The final page-rounded descriptor interval is clamped to the
effective range. This preserves tiny valid intervals and returns a null binding
when the limit cannot fit the prefix plus any payload. It does not reserve a
fixed 64 KiB or require the final descriptor length to remain page-aligned.

Vulkan forwards `Device::GetMaxStorageBufferRange`. OpenGL queries
`GL_MAX_SHADER_STORAGE_BLOCK_SIZE` with `glGetInteger64v`, stores u64, and uses the
same result for GLSL and GLASM bindings. Unlike the source port, a zero/negative
driver result becomes zero rather than being increased to an assumed minimum.

Writable table pools, ordinary native packed sizes, and active-DLSS bare-pointer
sizing keep their policies. Saturating the wide layout makes formerly wrapped
large ordinary sizes valid, so final interval arithmetic also remains u64 and
saturates to u32 maximum before narrowing. Representable ordinary intervals are
unchanged; near-u32-maximum sizes no longer wrap after prefix addition or rounding.

## Test-first evidence

All range tests call the real `StorageBufferBinding` through existing friend
access and a configurable fixture runtime limit. No replacement arithmetic
implementation is tested. Pool mappings allocate GPU page metadata only; no
large host buffer is created, uploaded, or read. The >u32 layout uses adjacent
same-kind GPU mappings that reuse physical ranges below 4 GiB. Test processes run
serially with the fixture's existing virtual guest RAM reservation.

Before production changes:
`& .\.local-tools\build.ps1 -LogName fog-red -RunTests -Filter '[buffer_ports]'`
built successfully, then failed **6 of 18 cases, 83 of 332 assertions** (seed
893395807). Actual bindings stayed at 64 MiB when 128/256 MiB were expected,
ignored small limits and alignment overhead, and narrowed a 4 GiB + 64 KiB layout
to 64 KiB. Evidence: `.local-tools/fog-red-build.log` and `fog-red-tests.log`.

A follow-up regression, before the final narrowing correction, used an ordinary
descriptor of `0xfffffff0` bytes at offset `0x123`. The actual read-only interval
wrapped to 3840 and the written interval to 19 instead of saturating. The
`[fog_range]` run failed exactly those **2 of 112 assertions in 1 of 4 cases**
(seed 1772609552). Evidence: `.local-tools/fog-narrow-red-tests.log`.

Coverage includes 64/128/256 MiB device limits, full 320 MiB mapping reach,
256/4096/65536-byte alignment, unaligned starts, page-end rounding, zero and tiny
limits, changing limits within one cache owner, >u32 layout, 1 GiB final ceiling,
device discontinuities, unmapped and sparse holes, null pointers, writable table
caps, ordinary packed sizes, and active/inactive native DLSS behavior.
