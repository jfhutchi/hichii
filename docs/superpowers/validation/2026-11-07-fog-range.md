## Adaptation

Read-only table pointers now reach the continuous mapped range, bounded by the
backend storage range and 1 GiB. The effective range participates in the binding
cache key. Layout lengths saturate in u64 before narrowing to u32. The actual
alignment prefix consumes the range budget; continuity is checked from the
aligned base. The final page-rounded descriptor interval is clamped to the
effective range. This preserves tiny valid intervals and returns a null binding
when the limit cannot fit the prefix plus any payload. It does not reserve a
fixed 64 KiB or require the final descriptor length to remain page-aligned.

Vulkan forwards `Device::GetMaxStorageBufferRange`. OpenGL queries
`GL_MAX_SHADER_STORAGE_BLOCK_SIZE` with `glGetInteger64v`, stores u64, and uses the
same result for GLSL and GLASM bindings. Unlike the source port, a zero/negative
driver result becomes zero rather than being increased to an assumed minimum.

Writable table pools, ordinary native packed sizes, and active-DLSS bare-pointer
sizing keep their policies. Final interval arithmetic remains u64. An ordinary
interval is rejected with a warning and a null binding if rounding its allocation
to cache pages would exceed u32. This includes the prefix between the cache page
base and the descriptor base. All cache-representable ordinary intervals remain
unchanged; unsupported near-u32-maximum intervals never reach allocation or host
binding as nonempty descriptors. The read-only table 1 GiB ceiling is unchanged.

## Test-first evidence

All range tests call the real `StorageBufferBinding` through existing friend
access and a configurable fixture runtime limit. No replacement arithmetic
implementation is tested. Pool mappings allocate GPU page metadata only; no
large host buffer is created, uploaded, or read. The >u32 layout uses adjacent
same-kind GPU mappings that reuse physical ranges below 4 GiB. Test processes run
serially with the fixture's existing virtual guest RAM reservation.

## Quality-review follow-up

Independent quality review of `f7e87d594d1072a9f2e0510e5c224eb2ea0ea708` found
that saturating the final descriptor to u32 maximum did not make its cache
allocation representable. `FindBuffer` calls `CreateBuffer`, which rounds both
ends to 64 KiB cache pages and narrows that span to u32. A descriptor at
`0x10000100` with length `0xffffffff` caused allocation span `0x100010000` to
wrap to `0x10000`; the descriptor's host offset plus length was `0x1000000ff`.

The new regression resolves the actual binding through `FindBuffer` and
`CreateBuffer`, then checks host offset plus descriptor length against the
returned buffer size. It allocates only the incorrectly wrapped small buffer on
the red implementation. Read-only and written cases run independently. It also
checks the largest representable interval without allocating gigabytes, rejects
one byte beyond that boundary, and resolves a small valid interval to a real
cache buffer to verify containment and continued allocation.

`& .\.local-tools\build.ps1 -LogName fog-consumer-red -RunTests -Filter '[fog_range]'`
built successfully and failed **4 of 128 assertions in 1 of 4 cases**, seed
270743236. Both access modes reproduced the invalid host interval over a 64 KiB
allocation and accepted the interval above the cache-page boundary. Evidence:
`.local-tools/fog-consumer-red-build.log` and `fog-consumer-red-tests.log`.

Production now checks the final descriptor against the largest whole-cache-page
allocation representable by u32, minus its actual cache-page prefix. The check
uses subtraction after a bounded prefix, so it cannot overflow while deciding
whether an interval is supported. Unsupported intervals log a warning and become
`NULL_BINDING` before u32 narrowing. The test proves their subsequent `FindBuffer`
resolution returns the null buffer and performs no cache buffer clear/allocation.
This change does not widen cache fields or change table-pool limits.
